# Desktop Experience

The desktop app is the main command-post surface and currently holds the broadest feature set. This document should track what the desktop app can do now, what condition those workflows are in, and where the UI needs standardization.

## Intended Users

- Incident command staff
- Planning staff
- Operations staff
- Logistics staff
- Safety staff
- Public information staff
- Communications staff
- Administrative users
- Unit leaders and section chiefs working from a command post

## Current-State Review Areas

- Which modules are accessible from the desktop menus?
- Which panels are complete enough to use?
- Which panels are placeholders, legacy, or partially migrated?
- Which workflows cross from one module into another?
- Which UI patterns are inconsistent between modules?
- Which modules need redesign before more features are added?

## UI Inventory Areas

- Menu-launched modules and tools
- Dockable panels and windows
- Dashboards
- Tables and lists
- Detail editors
- Forms
- Dialogs
- Status indicators
- Search and filtering controls
- Import/export actions
- Print, PDF, or briefing outputs where applicable

## Design Questions

- Which modules should open as dashboards, and which should open directly into management tables?
- Which repeated table actions should be standardized across modules?
- Which status labels and colors should be shared across the app?
- Which module relationships should be shown directly in the UI instead of hidden behind separate navigation?
- Which workflows need a guided step-by-step experience rather than standalone forms?
