SARApp Mobile API Contract - Current Server Alignment

Source of truth inspected:
- data/db/sarapp_db/api/app.py (LAN server API)
- Design Documents/Instructions/cloud_router_architecture.md (remote routing)

Server runtime:
- FastAPI application is created in data/db/sarapp_db/api/app.py and runs on
  the incident LAN server, which listens on port 8765 by default.
- cloud_server is a stateless reverse-tunnel router and has no MongoDB or
  sarapp_db router copy.
- Remote base URL: https://sarapp.arcadiacommandsolutions.com/r/<connect_code>
- Current default connect code: OURS-9165
- Remote health check: GET /r/<connect_code>/health
- Remote server metadata: GET /r/<connect_code>/server-info
- SARAPP_MONGO_URI is configured only on the LAN server.

Current MongoDB structure:
- sarapp_system: server/app state and incident registry
- sarapp_master: agency-wide reference data such as personnel, certifications, organizations, vehicles, aircraft, equipment, resource types, hazard types, radio channels, templates, and user profile scaffolding
- sarapp_incident_<incident_id>: per-incident operational data such as incident profile, teams, tasks, check-ins, check-in history, resources, comms logs, ICS forms, GIS, planning, logistics, safety, intel, approvals, and audit logs

Important terminology update:
- Use "incident", not "mission", for API contracts.
- Current server does not expose POST /api/mobile/login or JWT/token auth.
- Current mobile MVP should treat a successful tunneled GET
  /r/<connect_code>/health as server connection. The cloud router's bare
  /health endpoint only confirms router health and does not prove that an
  incident LAN server is reachable.
- If mobile auth is added later, it should be designed as a new server feature and documented separately.

MVP mobile endpoints:
- GET /health
- GET /server-info
- GET /api/incidents
- GET /api/incidents/{incident_id}/profile
- GET /api/incidents/{incident_id}/checkin/roles
- GET /api/incidents/{incident_id}/checkin/teams
- GET /api/incidents/{incident_id}/checkin/personnel/search?q={query}
- PUT /api/incidents/{incident_id}/checkin/{person_id}
- GET /api/incidents/{incident_id}/checkin/roster

Mobile-owned responder profile:
- Stored locally on the device using AsyncStorage.
- Includes personal info, certifications, assigned vehicles, and assigned equipment.
- During incident check-in, the profile is copied into the check-in request as mobile_profile_snapshot.
- The same request also sends common roster fields such as display_name, incident_phone, incident_callsign, role_on_team, team_id, vehicles, and equipment.
- Current target collection: sarapp_incident_<incident_id>.checkins.
